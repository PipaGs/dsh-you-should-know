# TypeScript conventions for `src/*.ts`

These rules applied to every phase that hardened the TypeScript sources. They
describe the final layout, the typing policy, and the exact local verification
loop. The migration design and phase plan are in [design.md](design.md); raw
evidence is under [migration/](migration/).

## 1. Source and generated output

- `src/*.ts` is the authored source. `lib/*.js` is generated by TypeScript 7 and
  committed, because a `github:` install runs no build step. Never edit
  `lib/*.js` by hand; change the source and run `npm run build`.
- `src/globals.d.ts` holds the ambient browser declarations. It is a
  declaration file and emits nothing.
- `src/client.ts` is a browser global script, not a module. It must contain no
  top-level `import` or `export`. The host module table injects it as classic
  script text, and three test files evaluate the raw file in `node:vm`. Adding
  module syntax makes the compiler emit an ESM module wrapper and breaks the
  contract. The project sets `moduleDetection: "legacy"` for this reason; do not
  remove it.
- `lib/client.js` starts with a `"use strict";` prologue that TypeScript 7 adds
  to script output. TypeScript 7 removed the `alwaysStrict` option (`TS5108`),
  so the prologue cannot be disabled. The client code uses no sloppy-mode-only
  construct, and the three client test files exercise the emitted file.

## 2. Strict typing policy

`strict` is on for the whole project. Every diagnostic must be fixed at the
source, not suppressed.

- Use real types: `interface` or `type` aliases for object shapes, unions of
  literal types for closed vocabularies, `readonly` for values that never
  change, and discriminated unions for outcomes that carry a kind.
- No blanket `any`. A parameter, return type, or variable may not fall back to
  `any` because the shape is inconvenient. If the shape is genuinely unknown at
  a boundary, use `unknown` and narrow it (section 3).
- No `@ts-nocheck`. No `@ts-ignore`. If a suppression is ever unavoidable, use
  `@ts-expect-error` with a one-line reason and a linked contract, and say why
  the type cannot be expressed. A suppression spans exactly one line.
- No non-null assertions (`value!`) used to silence real nullability. Handle
  `null` and `undefined` with an early return, a default, an explicit throw, or
  a filter that keeps the narrowed type visible to the compiler.
- Do not widen an internal type to satisfy a caller. Type the seam instead, or
  validate the caller's value.
- No enums, namespaces with runtime members, parameter properties, decorators,
  or `import x = require()`. `erasableSyntaxOnly` rejects them (`TS1294`), and
  Node 26 type stripping rejects them at runtime. Use `const` tables with
  `as const` and literal union types, and assign class fields in the
  constructor.
- `verbatimModuleSyntax` is on. A type-only import must be written
  `import type { Name } from './module.js'`; a value import stays a normal
  import. Do not rely on the compiler to erase a value import that is only used
  as a type.
- Every relative import keeps the explicit `.js` extension, because the emitted
  ESM files keep that specifier. Import only relative modules plus the single
  existing external package `@deepseek-ai/schemastery`. Do not add runtime
  dependencies.

## 3. `unknown`, narrowing, and external data

- Treat every JSON body, HTTP payload, host value, and session event field as
  untrusted first. Type it as `unknown`, then validate with `typeof`,
  `Array.isArray`, `Number.isInteger`, or a small type predicate.
- Prefer a named type predicate (`function isVerdict(value: unknown): value is
  Verdict`) over a cast. A predicate keeps the check and the type in one place.
- A cast (`as T`) is a last resort. It is acceptable only when a documented
  runtime contract guarantees the shape and the value was already validated.
  Never cast `unknown` straight to the target type to silence a diagnostic.
- Keep narrowing local. Do not widen a validated object back to `unknown` when
  passing it to a typed helper.
- Missing optional members are real cases. Decide behavior explicitly: a
  fallback, a bounded failure result, or a throw. Do not assume a property
  exists because the current host sends it.

## 4. DSH host seams and browser globals

- The plugin receives host seams through injection: `ctx`, `ctx.get('llm')`,
  `ctx.get('shell')`, `ctx.get('settings')`, `ctx.connection`, and
  `ctx.slots`. Declare narrow local interfaces for exactly the members the code
  reads or calls. Do not import host implementation packages, and do not model a
  seam as `any`.
- Keep the auth boundary visible in types: route handlers stay on the connection
  Fetch carrier. Never type or register a raw web-server route.
- Optional seams may be absent or throw. Type them as optional and keep the
  existing guarded behavior; do not assert their presence.
- `src/globals.d.ts` declares only the browser members `src/client.ts` reads
  today: `window.__ModuleLoader__`, `window` focus listeners, `document`
  visibility, and `navigator.clipboard`. Add a member only when the client code
  actually uses it, with the narrowest honest type.
- The compiler project loads `lib: ["ES2022"]` only. The DOM library is absent,
  so `@types/node` is the only source of Node globals (`fetch`, `Request`,
  `Response`, `setTimeout`, `console`), and `src/globals.d.ts` is the only source
  of browser globals. Do not add `"dom"` (or any other lib) to `tsconfig.json`;
  adding it puts the real `Window`, `Document`, and `Navigator` types back in
  scope, hides client nullability behind DOM types, and makes the ambient
  declarations conflict with the library. No blanket `any` in this file.
- Because the DOM types are absent, host code sees the Node `fetch` /
  `Response.json()` contract: a parsed body is `unknown`, not `any`. Validate it
  before reading fields. That strictness is intended; do not reintroduce `any`
  to silence it.
- The loader contract is `load({ id, factory(require) })`; `factory` returns the
  plugin bundle object and receives the host's CommonJS `require`. Model the
  return as `unknown` until the bundle object gets a real interface.

## 5. Comments and JSDoc

- Existing comments are documentation and carry the design rationale that
  `docs/reference.md` and the tests cite. Keep them when editing the code they
  describe. Do not delete, shorten, or translate them.
- Four legacy JSDoc lines use the invalid form `@returns { ... }`:
  `src/core.ts:1392`, `src/core.ts:1911`, `src/core.ts:2388`, and
  `src/language.ts:68`. In `.ts` they are plain comments and produce no
  diagnostic. If a later phase touches that block, normalize the line to either
  `@returns <description>` or a real TypeScript return type; do not rewrite the
  surrounding prose.
- Comments stay English (repository rule in `AGENTS.md`). A new comment explains
  an invariant or a bound, not the mechanics of the next line.
- TypeScript's emitter reprints the source. It leaves one trailing space when a
  standalone comment line starts a comma-separated list element (an argument
  list or a destructuring pattern). `test/pr-diff-check.test.js` rejects trailing
  whitespace in the diff. Keep such a comment on the previous element's line as
  a trailing comment; this is why `src/client.ts` and `src/core.ts` differ from
  the original JavaScript copies at those two spots.

## 6. Verification loop

Run this loop after every edit, in this order:

```sh
npm run typecheck      # tsc -p tsconfig.json --noEmit; target is 0 diagnostics
npm run build          # tsc -p tsconfig.json, writes lib/*.js
npm test               # npm run check:js && node --test test/*.test.js
npm run check:drift    # fresh build bytes must equal committed lib/*.js
git diff --check       # no trailing whitespace or space-before-tab in the diff
```

- `npm run typecheck` must exit 0 with zero diagnostics, and `npm run check` is
  green. The project sets `"noEmitOnError": true`, so `npm run build` fails
  without emitting any file on a diagnostic, and the drift gate returns exit 2
  instead of comparing a failed or diagnostic-bearing build. Do not pass
  `--noEmitOnError false` to force emission.
- The final gate is: `npm run typecheck` exit 0, `npm run build` exit 0,
  `npm test` 697 passing tests and 0 failures, `npm run check:drift` exit 0,
  `npm run smoke:local` exit 0, and `git diff --check` clean.
- `npm run check:drift` compiles into `node_modules/.build-check`, compares the
  emitted file set and bytes with `lib/`, and never writes `lib/` or Git state.
  `node scripts/check-build-drift.mjs --expected <dir> --out <dir>` compares
  against another tree, which is how the drift alarm itself was proven.
- `node --check` passes on the emitted JavaScript but never types-checks it; it
  cannot replace `npm run typecheck`.
- Do not touch `test/`. The suite is black-box against the emitted `lib/*.js`
  artifacts and already covers the migrated behavior.
