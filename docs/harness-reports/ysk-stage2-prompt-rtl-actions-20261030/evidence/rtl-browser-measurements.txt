METHOD:
A DOM Range around the first and around the last character of the note text.
The reported x is getBoundingClientRect().left in CSS pixels. The first logical
character of an RTL sentence must sit at the right edge; the final period must
sit at its left end.

CASE                     DIR ATTR   COMPUTED   FIRST CHAR X   LAST CHAR X
Hebrew current           none       ltr        61             318
Hebrew with dir="auto"   auto       rtl        687            410
Arabic current           none       ltr        53             283
Arabic with dir="auto"   auto       rtl        692            444

INTERPRETATION:
Without a base direction the first Hebrew character renders at x=61 (the left
edge) and the final period at x=318 (the right side of the run): the RTL
sentence is laid out in the inherited LTR paragraph direction. With dir="auto"
the first character moves to x=687 (the right edge) and the period to x=410
(its correct left end). Arabic behaves the same way. The mixed Latin path stays
a single left-to-right run inside the RTL paragraph.

The offline tests assert the markup contract (the note, explanation, and history
text nodes carry dir="auto"). They cannot assert glyph positions because the
node:test harness has no layout engine; this page is the rendering evidence.
